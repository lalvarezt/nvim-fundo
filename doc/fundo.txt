INTRODUCTION                                                 *fundo-introduction*

nvim-fundo makes Neovim's persistent undo files more stable when file contents
change outside Neovim.

Neovim stores undo history in native undo files. Fundo does not replace that
undo engine. If the file on disk no longer matches that native undo file,
Neovim may be unable to use the previous undo tree. Fundo keeps fallback
archives of recent file contents so the file and its native undo file can be
replayed as a matching pair.

Fundo also keeps a size-limited baseline snapshot for cases where no usable
native undo file is available. If a file later changes while Neovim is closed
and Fundo cannot load native undo, Fundo uses that baseline only to create one
normal native undo step from the previous file contents to the current file
contents.

==============================================================================
SETUP                                                               *fundo-setup*

Enable Neovim undo files and call setup:
>
    vim.o.undofile = true
    require('fundo').setup()
<

==============================================================================
CONFIGURATION                                               *fundo-configuration*

Default configuration:                                 *nvim-fundo-default-config*
>
    {
        archives_dir = vim.fn.stdpath('cache') .. path.separator .. 'fundo',
        limit_archives_size = 512,
        baseline_max_file_size = 8,
        retention_days = nil,
        track_on = 'open',
        filter = function(path, bufnr) return true end,
        logging = {
            enabled = false,
            level = 'warn',
            path = vim.fn.stdpath('cache') .. path.separator .. 'fundo.log',
        },
    }
<

                                                        *fundo-archives_dir*
`archives_dir`~
        Directory used to store fallback file-content archives and baseline
        snapshots.

                                                        *fundo-limit_archives_size*
`limit_archives_size`~
        Maximum archive directory size in MB. When the size is exceeded, older
        archive records are pruned by modified time. Fallbacks, baselines, and
        manifests, and committed generations all count toward this limit.

                                                *fundo-baseline_max_file_size*
`baseline_max_file_size`~
        Maximum individual baseline snapshot size in MiB. When omitted, this
        is the smaller of 8 and `limit_archives_size`. Set to 0 to disable
        baseline snapshots. An explicit value overrides the default.

        Earlier versions used `limit_archives_size` as the default. Set this
        option explicitly to your archive budget to retain that behavior.
        This limit does not restrict native undo preservation through fallback
        archives. Baseline capture checks the buffer size before copying lines.
        Persistence is deferred until the next main-loop turn and skips
        unchanged snapshots. Writes still run on the main thread. Unload,
        exit, and `:FundoSync` flush pending snapshots.

                                                        *fundo-retention_days*
`retention_days`~
        Optional maximum archive record age in days. Defaults to `nil`, which
        disables age-based expiry. Expired fallback, baseline, and manifest
        artifacts are pruned together.

                                                                *fundo-filter*
`filter(path, bufnr)`~
        Callback that returns `true` when Fundo should track a file. Defaults to
        accepting every otherwise supported buffer. Returning `false` excludes
        the file from fallback archives and baseline snapshots.
        Exclusion does not erase previously saved archives or disable Neovim's
        own persistent undo files.

                                                        *fundo-track_on*
`track_on`~
        When tracking starts for files without Fundo records. `open` is the
        default. `write` waits for the first write. `manual` waits for
        `:FundoTrack`. Existing records still recover on open under all policies.
        Explicit tracking respects `filter`, buffer type, and undo settings.

                                                        *fundo-logging*
`logging`~
        Logging configuration. Logging is disabled by default. When enabled,
        Fundo writes lifecycle, sync, archive, baseline, and failure events to
        the configured log file. You can also set `FUNDO_LOG` to one of the
        supported level names to enable logging without changing setup config.

                                                        *fundo-logging-enabled*
`logging.enabled`~
        Boolean. Enables or disables log writes. Defaults to `false`.

                                                        *fundo-logging-level*
`logging.level`~
        Minimum log level to write. Supported values are `trace`, `debug`,
        `info`, `warn`, and `error`. Defaults to `warn`.

                                                        *fundo-logging-path*
`logging.path`~
        Log file path. Defaults to `stdpath('cache')/fundo.log`.

==============================================================================
UNDO PRESERVATION                                             *fundo-behavior*

Fundo preserves undo history by keeping Neovim's native undo file and Fundo's
fallback archive in sync. Both artifacts are treated as a pair. A separate
baseline snapshot is used only when no usable native undo file is available.
Successful transfers also write a versioned manifest under
`archives_dir/.metadata`. Missing manifests from earlier Fundo versions do not
prevent recovery; diagnostics report those records as legacy.

Opening a file without editing it~
        With `track_on = 'open'`, opening an eligible file retains its contents, even
        if you never edit or write the file. For a file with no previous undo
        history or recovery archives:

        1. Open contents A. Undo history is empty. Fundo saves A as a separate
           baseline snapshot.
        2. Close Neovim without editing, then change the file externally to B.
        3. Reopen the file. The buffer contains B. `:undo` restores A, and
           `:redo` restores B.

        Reopening unchanged contents adds no undo step. Multiple external
        edits between opens become one combined change. Intermediate versions
        that Fundo never observed are unavailable.

        Baseline capture requires Fundo to be enabled, `undofile` to be on,
        and a named, supported buffer accepted by `filter`. The buffer must be
        clean, modifiable, and have undo enabled. The snapshot must fit
        `baseline_max_file_size`, and recovery requires it to survive pruning.

        `:FundoStatus` reports a saved baseline without a fallback as
        `baseline-only`. Set `baseline_max_file_size = 0` to disable baselines,
        use `filter` to exclude paths from Fundo tracking, or set
        `retention_days` to expire saved records. Neovim's persistent undo
        files remain independent of these controls.

Supported external-change cases:

- File changed while Neovim is closed:
  Fundo validates and repairs the undo file on the next `BufReadPost`.

- File changed while Neovim was closed and no native undo file is usable:
  Fundo creates one native undo step from the baseline snapshot to the current
  file contents. The baseline then advances after the repaired state is
  persisted.

- File changed while Neovim was closed and the fallback archive is missing:
  A committed generation can restore the matching history. For legacy records
  without generations, an unmatched native undo file prevents baseline-only
  recovery.

- Clean loaded buffer changed outside Neovim:
  `:checktime` lets Neovim reload the file and emit `FileChangedShellPost`.
  Fundo then restores the previous undo history around the new file contents.

- Dirty loaded buffer changed outside Neovim:
  Neovim keeps the unsaved buffer unchanged. Fundo does not replace dirty buffer
  contents with external changes.

- External overwrite, append, and truncate:
  These are treated as file-content changes and can be repaired when the matching
  native undo file and fallback archive are available.

- External deletion or rename of an open file:
  Fundo captures the buffer text with its undo tree, even if the source pathname
  no longer exists. Reopening the old path can recover that history. Fundo does
  not recreate or write the source file during synchronization.

- New files and buffer renames:
  `BufNewFile` and the first write attach new files. `:file` and `:saveas` update
  tracking to the new buffer name and apply the configured filter again.

Failed transfers retain a matching text and undo snapshot for retry after buffer
unload. Newer saved state takes precedence over an older pending snapshot.
Snapshots use Neovim buffer text, independent of source encoding and line endings.
Baseline-only records remain eligible for recovery until age or size pruning
removes them. Diagnostics report these records as `baseline-only`.

Fundo also syncs dirty undo state during lifecycle events such as `BufUnload`,
`VimLeave`, `VimSuspend`, `TermEnter`, and `FocusLost`.

Committed generations~
        Recovery transfers store checksummed text and undo data in the private
        `.generations` directory. An atomic pointer publishes a complete
        generation. The previous complete generation remains available if the
        current generation is damaged. Incomplete generations are cleaned on
        startup or the next successful save. Old archives migrate on save.

        Per-record locks and version checks prevent stale Fundo sessions from
        replacing newer archives. A conflict remains pending. Preserve local
        edits and reopen the file before retrying. Dead locks on the same host
        are reclaimed. Native undo files remain under Neovim's control.
        Generation copies protect recovery from competing native undo writes.
        Process interruption is covered; power-loss durability is not promised.

File moves are not a complete recovery guarantee. Fundo tracks the path Neovim
reports for a buffer and follows paths changed with `:file` or `:saveas`, but arbitrary
external move/rename recovery is still future work.

==============================================================================
TROUBLESHOOTING                                          *fundo-troubleshooting*

E211 after deleting or renaming an open file~
        Neovim reports a missing source during `:checktime`. Fundo can still
        archive the loaded buffer. After an external rename, use `:file new-path`
        to associate that buffer and its history with the new path.

No undo history after an external change~
        Fundo first tries the last complete committed generation. For legacy
        records, the native undo file and fallback archive must match. If the fallback
        archive is missing while a native undo file exists, Fundo fails safely
        instead of replacing that history with a baseline-only step. If no usable
        native undo file is available, a baseline snapshot can provide one native
        undo step when the file fits `baseline_max_file_size`. A corrupted
        native undo file may still make Neovim abort the edit before Fundo can
        repair the buffer. Use `:FundoStatus` for the current file and
        `:FundoDoctor` for archive-wide diagnostics.

Archive directory uses disk space~
        This is expected. Lower `limit_archives_size` to prune old fallback
        records more aggressively, set `retention_days`, or use
        `baseline_max_file_size` and `filter` to limit what is stored.

Archive directory was deleted~
        Fundo recreates the configured archive directory when syncing undo state.

Dirty buffer was not replaced by an external file change~
        This is Neovim's safe behavior for modified buffers. Write, reload, or
        discard the buffer explicitly after reviewing the change.

API                                                                 *fundo-api*

                                                        *fundo.track()*
                                                        *:FundoTrack*
`require('fundo').track({bufnr})`~
        Start tracking a named, loaded buffer. Defaults to the current buffer.
        Returns true or raises an error if the buffer is ineligible or Fundo
        is disabled. Resumes a buffer stopped by `:FundoForget!`.
        `:FundoTrack` applies to the current buffer.

                                                        *fundo.forget()*
                                                        *:FundoForget*
`require('fundo').forget({target}, {opts})`~
        Preview Fundo record removal for a path. Defaults to the current file.
        A directory selects its descendants. Set `opts.project = true` for a
        project directory that no longer exists. Returns `records`, `bytes`,
        `errors`, `unidentified`, `removed`, and `applied`.

        Set `opts.apply = true` to remove the selected Fundo records and stop
        tracking those paths for this Neovim process. Native undo files and
        buffer contents remain. Other sessions can still capture these paths.
        `:FundoTrack` resumes an individual buffer. Use `filter` for a persistent
        exclusion. Records with unidentified source paths are reported and kept.

        `:FundoForget [path]` previews removal. `:FundoForget! [path]` applies it.

                                                        *fundo.setup()*
`require('fundo').setup({opts})`~
        Configure and enable Fundo. Calling setup repeatedly reloads the
        configuration and restarts the plugin.

                                                        *fundo.enable()*
`require('fundo').enable()`~
        Enable Fundo with the current configuration.

                                                        *fundo.disable()*
`require('fundo').disable()`~
        Disable Fundo and dispose its event handlers.

                                                        *fundo.status()*
`require('fundo').status({target})`~
        Return structured preservation status for the current buffer, a buffer
        number, or a file path. `:FundoStatus [path]` prints the same information.
        Path status includes pending transfers after the buffer closes.
        `baseline` includes `eligible`, `reason`, `limit` in bytes,
        `buffer_size` when available, and `capture_state`. Reasons include
        `baseline-disabled`, `oversized`, `undo-disabled`, `modified`,
        `not-modifiable`, `filtered`, `unloaded`, and `plugin-disabled`.
        `captured_at` is the Unix capture time when recorded in the manifest.
        A missing snapshot reports `not-captured`; absence alone does not
        establish that a record was pruned. Status inspection does not capture
        or persist a snapshot.
        `last_error` is nil or a table with `stage`, `message`, and `time` as a
        Unix timestamp in seconds. Stages are `capture`, `fallback`, `undo`,
        `baseline`, `manifest`, and `generation`. The command prints the time in local time.
        A failed save without a pending snapshot has state `transfer-error`.
        With a retained snapshot, the state remains `pending-transfer`.
        A successful retry clears the error. Error details remain in memory
        while the buffer is tracked or its snapshot awaits a detached retry.
        They do not survive restarting Neovim.

                                                        *fundo.doctor()*
`require('fundo').doctor()`~
        Return an archive-wide health report. `:FundoDoctor` prints the report,
        including usage, legacy and expired records, pending transfers, invalid
        manifests, orphaned artifacts, and permission problems.
        Pending transfers make `ok` false until saved. The count includes open
        buffers and detached retries, counting each archive once.
        Save failures also produce `transfer-error` issues with the source path,
        failed stage, and error message, including failures during capture.

                                                        *fundo.sync()*
                                                        *:FundoSync*
`require('fundo').sync()`~
        Persist recovery snapshots and retry pending transfers. Includes modified
        tracked buffers without writing their source files. Returns a promise
        that resolves on completion or rejects on failure, including when Fundo
        is disabled. Successful transfers remain saved if another transfer fails.
        Runs archive cleanup when the manager's hourly scan is due.

        `:FundoSync` performs the same operation and reports completion or failure.
        Enable Fundo with `:FundoEnable` before syncing.
